# 图像兼容与交付 QA

## 1. 先核对保存内容

打开最终文件而非内存中的设计对象，确认页数、顺序、来源备注和关键数字。图中“实际”“历史”“拟议/机制示意”的身份必须与材料一致。

文字、表格、数据图和要求可编辑的流程图保持原生对象；图片独立嵌入，不把整页变成一张图。图中的重复值来自同一数据定义，不能图例、备注和正文各写一套。

## 2. 图像兼容检查

某些软件优先显示 SVG 对象的备用位图。如果导出工具只写了 SVG，并给备用 PNG 放入透明一像素占位，渲染器可能看起来正常，另一个软件却看不到图标或 logo。

独立 skill 自带的检查器不修改 PPTX，仅使用 Python 标准库：

```bash
python3 <skill-directory>/scripts/inspect_pptx_images.py final.pptx --fail-on-error
```

它按使用中的图片关系定位 SVG 与同一对象的备用图，区分已确认错误与无法验证的格式。普通一像素图、未引用素材不应被误报成 SVG 备用图错误。对不支持的编码，读报告中的未验证项，不能把“未验证”说成“通过”。

在完整仓库中，也可使用整合入口：

```bash
python3 scripts/inspect-pptx.py final.pptx --expected-slides 2 --check-image-fallbacks
```

上例中的 `2` 只是示例，改为实际要求的页数。

发现空白备用图后，优先为该图片嵌入足够清晰的 PNG，或由原始矢量重新生成有效备用图；保留图像比例和来源。不要用截图整页替代原生文字、表格或机制图。检查器不负责修复，也不能证明品牌素材使用权限或视觉清晰度。

## 3. 每页目视检查

以正常阅读尺寸查看每一页：

- 中文字形、标题与正文是否完整，缩略后是否仍能辨认关键标签。
- 图是否显示实际的信息转换，而非只在标题旁添加小符号；表格、网络和模型关系是否与当前题目一致。
- 图标、logo 是否清楚且对应真实工具；图片是否拉伸、缺失或裁掉关键坐标与图例。
- 连接线是否碰到正确对象，审核、失败、补证和返修的去向是否明确。
- 文字是否压线或越界，颜色、线型和标签是否一致，限制条件是否被藏到看不见的位置。

有 LibreOffice/Poppler 时，可在完整仓库运行：

```bash
python3 scripts/render.py final.pptx --out build/preview
```

若目标设备缺字体，选择实际可用且符合参考的字体后重新检查。渲染 PDF 不表示已经打开 PowerPoint；包结构正常也不证明数据、科学结论或页面好看。

## 4. 验证范围与交付

修改仓库代码后运行仓库要求的测试和 demo。Skill 的入口与安装元数据需要单独校验；基础校验不等于真实任务试用。

对外只报告已完成的检查。交付用户指定的 PPT/页面与必要说明，内部脚本、测试素材和渲染中间件留在工作区。公开仓库只提交通用方法、合成测试和获准公开的资产，不把真实项目输入或原始交付文件当示例上传。
